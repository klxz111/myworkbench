## 预案：三组功能按优先级串行做扎实（A 循环+拖拽 → B 编辑+上传 → C 分页）

已确认：本轮不做工作流整合；循环任务采用**单文件推进模型**（完成一次，due_date 自动推进到下一周期，不生成历史记录）。零新增数据模型/表，全部复用 frontmatter + 现有 PUT 合并语义（PUT 会展开合并 existing.frontmatter，新增 recurrence 字段天然在所有写路径中存活）。

### 工作流 A：循环任务/事件 + 日历拖拽改期

**A1. 数据模型（纯 frontmatter）**
- task / event 新增两个字段（fields.ts）：`recurrence`（select：不重复/daily/weekly/biweekly/monthly/yearly）、`recurrence_until`（date，可选）。锚点 = `due_date`（task）/ `event_date`（event）。
- `src/lib/date-utils.ts` 新增共享纯函数 `nextOccurrence(date, freq, from?)`：daily +1d；weekly +7d；biweekly +14d；monthly/yearly 按日历月/年推进并 clamp 月末（锚点 31 号→2 月 28 号）。客户端（完成推进）与服务端（展开）共用。

**A2. 展开逻辑（src/lib/due-items.ts）**
- 新增 `expandOccurrences(anchor, freq, until?, horizonDays)`，在 collectDatedItems 的 task/event 分支：有 recurrence 时展开为虚拟 DatedItem（id=`${id}@${date}`，href 不变，日历 API 与 day-detail 键控零改动）。
- task 只推 ≥今天的发生日（当前待办 + 未来，杜绝幽灵逾期）；event 推锚点后 ≤180 天全部发生日（纯展示）；单实体上限 100 个发生日。

**A3. 完成推进**
- 新建共享客户端 helper `advanceRecurringTask(task)`：有 recurrence → PUT `{data:{due_date: nextOccurrence(...)}}`（status 保持 todo）；无 recurrence → 原 PUT `{data:{status:'done'}}`。
- 接入三处完成入口：CalendarClient.completeTask、TodayClient、TasksClient 勾选。
- 前提修复：列表 API `/api/entities/[type]` 目前只返回 id/title/status/tags/updated_at（recon 证实 TasksClient 的 dueMeta 永远 undefined）→ GET 按 type 白名单补充字段：task 补 due_date/recurrence，event 补 event_date/recurrence。

**A4. 日历拖拽改期**
- 照抄 BoardClient 的 HTML5 DnD 模式到 CalendarClient：条目 draggable、日期格 onDragOver/onDrop → PUT 对应日期字段 → load(year,month) 刷新。
- 支持 4 类顶部字段日期：task→due_date、event→event_date、person(followup)→next_action_date、opportunity(deadline)→deadline；**gate 不做拖拽**（gate 是嵌套对象，整对象替换有覆盖风险，保留编辑直达）。
- 循环条目拖拽语义 = 移动锚点（下一发生日变为落点日）。

**A5. 表单**
- EntityForm 由 fields.ts 驱动，recurrence 字段自动出现；独立表单 EventEditClient 补 recurrence/recurrence_until 两个控件。

### 工作流 B：编辑分屏预览 + 图片上传

**B1. 分屏预览**
- EntityForm 的 content textarea（唯一咽喉点，覆盖全部 15 类实体 + 决策专用编辑页）改为三态切换「编辑 / 分屏 / 预览」，分屏用 `grid lg:grid-cols-2`（复用 workspace MarkdownEditor 已验证的布局），右侧复用现有 MarkdownPreview（prose dark:prose-invert，防抖已内建）。

**B2. Markdown 工具条**
- 复用 workspace MarkdownToolbar 的按钮集，把 insert() 改造为支持 textarea（selectionStart/End 拼接）：加粗/斜体/标题/列表/引用/代码/链接 + 新增图片按钮。

**B3. 上传 API（新路由）**
- `src/app/api/upload/route.ts`（nodejs runtime）：POST multipart formData；扩展名白名单 png/jpg/jpeg/gif/webp（**不含 svg**，内联渲染有 XSS 面）；服务端生成文件名（时间戳+随机）；写入 `workspace/attachments/YYYY-MM/`（复用 getWorkspaceRoot）；返回 `{path}`。
- `src/app/api/asset/route.ts`：GET `?path=` 二进制服务——safeJoin 限定 workspace 根 + 扩展名→Content-Type 白名单 + Cache-Control。Markdown 引用 `![](/api/asset?path=attachments/...)`，实体预览与 workspace 预览均能显示。
- 上传 UI：EntityForm 工具条图片按钮 + 隐藏 file input，成功后光标处插入 markdown；workspace MarkdownToolbar 同步加图片按钮。
- 检查 `/api/export` 的 zip 范围，若不含 workspace/attachments 则补上，保证附件随备份走。

### 工作流 C：列表分页 + 性能 + 顺手修

**C1. API**：GET `/api/entities/[type]` 加可选 `?limit=&offset=`（带 limit 返回 `{items,total}`，不带保持旧数组形状，零破坏），顺带 `?status=&tag=`（tags 用 json_each）；db.ts 新增复合索引 `(type, updated_at DESC)` + 排序 tiebreaker id。

**C2. sync 快路径**：syncMarkdownToSqlite 每请求全盘重扫是真正热点 → 目录级 mtime+size 变化才重扫该类型（CLI/validate 保留 force 全量）。

**C3. 客户端**：10 个纯列表页（evidence/belief/strategy/research/experiment/people/organizations/opportunity/profile/events）接「加载更多」；ListControls 支持服务端 facets（SQL GROUP BY 随响应返回，避免下拉选项随加载截断）；research/projects 跨类型 join 只分页主类型；TasksClient/BoardClient 保持全量。

**C4. 顺手修**：DecisionsClient 门控徽章永远"未设置审核日期"（列表 payload 无 gate → 从 /api/entities/decision/gates 合并）；删除死文件 src/app/opportunity/OpportunityClient.tsx（页面实际用 OpportunitiesClient，两者功能已相同）。
