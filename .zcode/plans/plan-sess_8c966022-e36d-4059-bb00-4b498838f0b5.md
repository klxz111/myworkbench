## RSS 订阅：信号源进工作台

### 架构决策
- **抓取在服务端** API 路由做（绕 CORS；E2E 用真实源验证本机出网）。解析用新依赖 `rss-parser`（RSS2/Atom/RDF 都支持）。
- **存储**：SQLite 新增两张**独立表** `rss_feeds` / `rss_entries`——与 entities 缓存平行的"源数据缓存"，不参与 Markdown 同步；条目摘要服务端去 HTML 存纯文本（前端不渲染原始 HTML，规避注入）。
- **已读状态**存 `rss_entries.read` 列（刷新/跨会话一致，未读数服务端算）。删库重建后订阅可重抓、已读会丢（记档）。

### 实现
1. **`src/lib/rss.ts`（新）+ db.ts 建表**：`rss_feeds(id, title, url UNIQUE, site_url, description, created_at, last_fetched_at, last_error)`；`rss_entries(id AUTOINCREMENT, feed_id, guid, title, link, author, published_at, summary, read DEFAULT 0, fetched_at, UNIQUE(feed_id,guid)，guid 缺省用 link)` + 索引；`fetchFeed()`：10s 超时 → 解析 → UPSERT → 每源只留最新 300 条；TTL 30 分钟惰性刷新。
2. **API**（`src/app/api/rss/…`，均 nodejs runtime）：`feeds` GET（列表+未读数）/POST（加源+首抓，校验 http/https 与重复 URL）；`feeds/[id]` DELETE（连带条目）；`entries` GET（`?feedId=&unread=1&limit=&offset=` → `{items,total}` 分页）；`entries/[id]` PUT（切已读）；`refresh` POST（全部或单源重抓，返回每源结果）。
3. **/rss 页面**（「记录」组新入口 + 命令面板）：左列源列表卡（标题+未读徽章+错误标记+删除✕），右列条目卡（未读圆点、外链标题、来源+日期、两行摘要、标已读/未读、**存为证据**）；顶部「全部/未读」筛选 + 「立即刷新」；全部 token 化样式 + 空态/错误态。
4. **存为证据**：复用现有 `POST /api/entities/evidence`——`source_type='news'、source_url=原文链接、summary=摘要、tags=['rss']`，字段与你证据链完全对齐，存完自动标已读。
5. 首抓成功的测试源（arXiv cs.LG，贴合你的研究方向）保留作种子示例，其余测试数据清理。
